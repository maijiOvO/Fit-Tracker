## 3. 改坏验证

### 3.0 先核对：等的条件不是断言本身

判别原则：只删「等界面画完」的 sleep；跟防抖、节流、手势时长有关的，要么保留，要么改成等它的结果。
「不该发生」的否定断言不能用轮询去等（一进来就成立＝永远绿），只能等它的**起因**先发生，或者保留原来的窗口。

| 原来的等待 | 换成 | 断言是什么 | 为什么不是同一件事 |
|---|---|---|---|
| 删除后 5.6 s「撤销条到期」（seeded-delete-survives） | 等 mock 收到删除后那次防抖 PUT 的**尝试**（`putAttempts`，被拒也算） | 重开后被删的那场没回来 | 等的是「推送试过了」，断言的是拉取合并后的列表 |
| 重开后再等 500–1000 ms（5 处） | `relaunch()`：`networkidle` + `<html data-fitlog-boot="done">`（启动流程走完才打）+ 三帧 | 合并后的单位 / 列表 / 迁移结果 | 标记只说明「启动流程走完了」，不带任何数据 |
| 1.5 s「等上一条防抖推送落地」（4 处） | `quiesce()`：`cancelPendingPush()` + `flush()` | 塞进去的夹具合并进来了 / 拉取失败不推送 | 作废排队的推送，和断言的数据无关 |
| 5.6 s「撤销条到期」（seeded-resumed-emptied） | 删掉 | — | 训练页删动作 2026-10-18 起不出撤销条，等的东西不存在 |
| 结束后 2.5 s（2 处） | 等刊末页出现再点掉 | 计划关联 / 时间线多一张卡 | 刊末页出现≠数据对 |
| 组号连点前 650 ms ×5 | 删掉 | 做完 / 退回 / 扫动 | 组号唯一的时间窗是长按加递减**达成后** 600 ms 吞一次 click（`SetCapsule.onSetNumClick`），这几下之间没有长按 |
| 长按 750 ms ×7 | 550 ms（真实阈值 500） | 菜单出来、松手不误触 | 手势时长本身保留，只去掉多余的 200 ms |
| 弹层动作连点 600 ms | 从上一次点击凑够 470 ms（450 ms 去重） | 一下加一张、再点取消 | 业务时间窗保留；等完再数一次，「一下加两张」照样露出来 |
| 「点完等 300 ms 再读界面」（约 40 处） | `settle()` 三帧 / 等弹层 detached / 等行数变化 / 等底栏回来 | 各自的值 | 等的是渲染周期或界面结构，读的是值 |
| 英文扫雷每屏 300 ms | `domQuiet()`：body.innerHTML 长度隔 100 ms 不变 | 扫到汉字 | 只等某个元素会漏扫没画出来的部分（假绿），所以等整页安静 |
| 「不该写墓碑」「改名不该被接受」等否定断言 | 保留原窗口，或先等它的起因（拉取发出去了、提示条 / 弹窗关闭哪个先来） | 否定断言 | 见上：否定断言不轮询 |

## 5. E2E_ONLY 用法与依赖表

```powershell
$env:E2E_BASE='http://localhost:3100'; $env:E2E_ONLY='set-state-gestures'; node scripts/e2e-smoke.mjs
```

- 逗号分隔多项；每项是**名字前缀**（`seeded-gym`），或 **`/正则/`**（`/^region-(drag|layout)/`）。
- 选中的步骤连同它的前置（递归）一起跑，启动时打印「选中哪些、连带哪些前置」。实测 `E2E_ONLY=set-state-gestures` 跑 8 步、12.6 秒（整套约 2 分钟）。
- 一个步骤都没选中的套件整套不起：只挑主流程的步骤时，带夹具那套不开 context、不灌种子，备份那套也不跑（原来 `E2E_ONLY=seeded` 仍会把 e2e-backup 整套跑完）。`E2E_SKIP_BACKUP=1` 可单独关掉备份。
- 中间有步骤被跳过、下一个要跑的是「从首页开始」的步骤（表里标 `H`）且上一个跑过的不是它的前置时，先 `resetHome()`：收刊末页 / 弹层 / 首选项，离开训练页并放弃进行中的那场。整套跑时不会触发。
- 新加的步骤必须先在依赖表里声明，否则 `step()` 直接报错。
- 规则代码在 `scripts/e2e-plan.mjs`，表在 `scripts/e2e-smoke.mjs` 的 `MAIN_STEPS` / `SEEDED_STEPS` 和 `scripts/e2e-backup.mjs` 的 `BACKUP_STEPS`。

## 6. 延后没做的

1. **seeded-stack-start-and-drop-order 整条没动**（任务第 7 条 + 开头那处等防抖的 800 ms，即原说明里的 1251 行）。
   卡在：另一个会话在改这条（横划断言），截至 2026-10-21 晚 main 上还没有它的提交。它现在是带夹具里最慢的一步（约 14 s）：
   拖大图两段循环每挪一下 `inputValue()` 一次（2 段 × 2 个方向 × 30 步＝120 次），外加两张只当设计稿、不做断言的 `card.screenshot`。
   等对方提交后从 main 拉最新再改：拖动改成拖完读一次值（或在页面里监听记最小值），两张截图删掉（手测清单「配重片设置面」已有对应项）。
2. **e2e 里的数值断言没有精简成「接线接上了」**（任务第 4 条后半）。node 检查已经补上并证明对坏逻辑会失败（见 3.1），
   但 e2e 里那些数（185 → 200、-4.4 lbs、20 → 10……）每条只是一个数据点，本身就在证明「接线接上了」，断言不花时间，删了一点不快、只会少一层整合覆盖。所以保留。
   重名规则（改名撞上别的动作的现名 / 曾用名）在 `ExercisePrefsContext.renameExercise` 里、依赖 context 状态，不是纯函数，没挪；e2e 的 rename-exercise-from-card 照旧守着。
3. **seeded-* 少做整页重载**（任务第 6 条）只做了一半：`relaunch()` 不再额外死等；gym 那几步的夹具没有合并进开头的种子 ——
   种子一多会改变首页布局和前面长按菜单用例的位置（seedWeights 不进初始快照就是这个原因），收益约 1 s，不值得冒这个险。
4. **待查：启动后过早点「开始训练」会被吞**。单跑 seeded-gym-weight-per-gym 时，`<html data-fitlog-boot>` 一打上就点底栏「＋」，
   点击无效（1.5 s 后仍在首页、没有弹窗），稳定复现；多一次 CDP 往返（约 20 ms）或等 `networkidle` 就好。
   `relaunch()` 因此保留了 `networkidle`。根因没查到 —— 真机上冷启动后立刻点「＋」可能也会遇到，值得单独看。
5. **main 在这期间前进了两个提交**（537ea4f「全局精简提示文案」、a8b7dac），都没改测试脚本，但改了提示文案；本分支合 main 后的兼容性见第 2 节末尾。
