总分的单位是「标准组」（想一下 + 点一个 48 dp 的目标，见标准 §7）：T1 相当于记 64 次标准组的精力，T3 相当于 22 次。

- **T3 稳态一组正好 1.00 分（2.00 s）**：一个 M + 点一下 48 dp 的组号，就是标准组本身。任何 App 记一组都少不了「想一下 + 点一下」，这是这套规则下点组号这条路的下限；再往下只有不用瞄准的大目标（见下节第 1 条）。
- **T3 一场 = 20 个标准组 + 开场 1.0 + 收尾 1.1**：开场是首页一下「上次 · 再练一次」，收尾是顶栏「结束训练」同一键点两下，全程没有弹窗、没有滚动。
- **认知占大头**：T1 里 M 占时间的 54%，T3 里占 68%。再省主要靠**少让人想**：少换屏、少输入值。
- **T1 的精度大头是打字**：31 个键共 49 比特，占全场四分之一；剩下的主要是 38–40 dp 的输入格和 ± 键，每次 2.5 比特上下。
- **视觉几乎等于时间**：T1 只剩加动作时的一次横滑不用看屏幕，记组的每一步都得盯着。

换到下一个动作不再自己滚：上一个动作最后一组点完，页面跟着指针滚到下一张卡（改前每个动作多一次 0.42 s 的滚动，不计分）。

改值有两种走法时取较快的。± 键和打字各是一个值单元（一个 M），差别在打字要弹键盘、按「下一项」，± 要连点：
E3-s2、E4-s3 用 ± 明显快（约 7.0 对约 8.0）；E1-s2 加 4 下才到 60，两种走法几乎一样；E5-s3 的 17.5 只能打字。
在这套规则里连点并不贵：第 2 下起只算 0.28 s、0 比特、不加 M，按 4 下比按 1 下只多 0.07 分；贵的是打字，每个键 1.58 比特。

## fitlog 开销不是最低的地方

按 T3 总分能省多少排序（括号里是 T3 的分 / 秒，在序列上改掉这一处后用同一套规则重算，`fitlog_walk.py` 开关名在括号里）。这些是这套标准量出来的事实，改不改另议。

1. **记一组没有不用看的走法**（`bottom=3`：T3 −7.2 分、T1 −4.7 分）：组号要瞄准，所以每组都得把视线从杠铃上移开。换成闭着眼也点得中的大目标（短边 ≥ 192 dp，比如底部半屏点击区＝「指针下那组做完」），一组的精度从 2.3 比特降到约 1 比特，点那一下不计视觉。
   343 × 56 的底部按钮（健身房训练的 `LOG NEXT SET`，`bottom=1`）在这套规则里和 48 dp 的组号几乎一样（短边 56），T1 反而更远更贵；要「不用看」就得到 192 dp。
2. **组号再放大**（`setnum=63`：T3 −1.2、T1 −1.1）：63 dp 以上命中率到 1.00，但行高要跟到 63，一屏少看两行。
3. **首组、改重量要弹系统键盘**：每次多一个 R键盘，重量到次数还要按一下「下一项」，每个键还要 1.6 比特。自带数字键盘（`keypad=1`）只省等待，总分 −0.2；键盘「完成」顺手做完这一组（`kbdone=1`，Lyfta 的做法）T1 −0.5，和 §12.6「点组号才算做完」冲突。
4. **± 到不了的数只能打字**（`halfstep=1`：T1 −1.6）：E5-s3 的 17.5 在一档 5 的龙门架上要打字（8.92 s、5.0 分）；馆档案里给龙门架一块 2.5 的加片、± 行多一颗 +2.5，这一组变成 7.3 s、3.4 分。
5. **「同上组」要两下**：添加组 + 点组号。规则是「点组号才算做完」，所以这一组的下限就是两次瞄准；能一下搞定的只有「预铺好、点一下」的 App（T3 的 fitlog 就是这样）。
6. **没有热身组类型**：E1-s1 只能按普通组记，和正式组混在一起。补上后标热身要多点一下（`warm=1`：T1 +0.6），T3 复制带标记、不变。

2026-10-26 改掉的（`old=1` 还原）：组号 36 → 48（T1 −1.3、T3 −1.4）；开练不再弹选馆（−0.9 / −1.1）；结束确认框改成同键再点一次（−1.1 / −1.1）；首页一键「再练一次」（T3 −0.8，叠上不问馆后开场从 2.9 分降到 1.0）；换动作自动滚（0 分、−1.7 s）。合计 T1 67.3 → 64.1，T3 26.6 → 22.1。
