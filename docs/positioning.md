# 产品定位

> 依据是国内外力量训练记录 App 的一手用户反馈（应用商店差评、Reddit、小红书、B 站、知乎）。
> 这里只留会左右产品取舍的结论；做新功能、写对外文案、定价之前先对一遍。

## 一句话

**认得你健身房的训练本**：按你这个馆真有的片子和器械记，离线、不注册、数据随时带走。

## 给谁

- **在意数字、会记录、会换馆的举铁用户**。「换馆重量对不上」只对这群人是痛点，他们正好是记录 App 的用户；
  劝「别钻牛角尖」的人不是目标，不去说服。
- 被订阅和免费上限卡住、又不想交月费的老练用户（Strong / Hevy 流失用户、训记用户）。
- 安卓用户：海外安卓口碑最好的 FitNotes 界面老、备份手动、没有多馆；国内装不了 Google Play 版的海外 App。

## 刻意是什么

- **快**：录一组点一下，上次的数就在旁边。老手留下来的主因是组间录入的点击数，不是功能多少。
- **可靠**：头号愤怒来源是丢数据——换机、重装、改账号制清空记录，以及「App 哪天停运、数据带不走」。
  纯本地不等于可靠（FitNotes 因备份要手动被骂），**自动备份必须显眼**：数据在哪、上次备份是什么时候，一眼能看到。
- **数据归用户**：导入 Strong / Hevy CSV、导出普通 CSV（Excel 直接打开）与完整 JSON，都免费。
  导出结构清楚就等于「能交给自己的 AI」，不必自己做 AI。
- **懂真实健身房的器械**：每个馆一份器械档案，自动给出的重量落在这个馆挂得出来的数；
  器械纪录只和同一个馆比，杠铃 / 哑铃跨馆比。差异要讲「馆」和「片」，不讲「支持磅」——按动作切 kg / lb 别家早就有。

## 刻意不是什么

- **不做 AI 教练、社交动态、动作视频库、饮食记录。** 老练用户的好评里，「没有这些」本身被点名夸；这些也是「臃肿」差评的来源。
- **不把基础功能锁进付费。** 配片、计时、图表历史、导出被锁是最招恨的做法；界面上不出现任何锁着的入口——
  泛人群看到一个 Pro 标就把整个 App 归成「要钱的」。
- **不做功能堆砌和高频发版。** 竞品的近期差评几乎都是「更新把东西弄坏了」和「功能多到不会用」。

## 竞品留下的空白

| 空白 | 现状 |
|---|---|
| 同一个动作在不同馆的器械上重量对不上 | 没有记录 App 真正解决；用户的变通是把动作复制成「腿举（A 馆）」。Hevy 的馆标签只是装饰，官方说下一步做按馆算 PR——这条差异不会一直独占 |
| 自动重量挂不出来（只有 2.5 的片还让加 1.75） | 别家的可选片设置不影响建议重量 |
| 单位跟着动作走、换馆要手动切；导入时 lb 被当成 kg | Strong 的 CSV 没有单位列，导入必须让用户按动作确认 kg / lb |
| 数据带不走 | 训记把导出锁在会员里；Strong 的 CSV 导不回来 |

Hevy 做出按馆 PR 之后，fitlog 守的是它路线图里没有的三样：**按片取整、单台器械的单位与一档、不联网不注册**。

## 由此而来的产品原则

1. **新功能先问「这是不是馆和片的问题」。** 研究里冒出的需求线索都在这条线上：每边挂哪几片、每台器械的设置备注
   （座椅档位、挂钩孔位）、挂片式器械的空载重量、没有小片时怎么加重。
2. **自动加重要透明**：「次数到上限就加这个馆这件器材的一档」，只在底稿上提示，不替人改数；不做黑箱算法。
3. **统计口径做对**：哑铃容量按双边、PR 对所有动作生效、按时间段比较。这些是竞品被点名的坑，成本低。
4. **上手两步：选馆 → 开练。** 卖点藏在选馆弹层里，新用户不建馆就看不到它。
5. **承诺写在显眼处并守住**：数据不会跟着 App 消失、现有功能不收费。用户对独立开发最大的不信任是「说好买断，后来改订阅」；
   以后要收费只收一次性买断。
6. **对外文案用用户的处境说话**：第一句讲「换个馆不用再从头试重量，同一台器械只和自己比」，而不是「馆档案」这个功能名。
   推广去「多馆怎么记」「kg / lb 混用」这类求助帖下作为解法回答并表明作者身份，不发自荐帖。
7. **国内分发**：国内安卓商店上架通常要软著和 App 备案；起步走可直接下载的 APK 页与 GitHub Releases。
