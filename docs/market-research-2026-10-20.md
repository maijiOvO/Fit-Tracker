# 竞品调研与定位（2026-10-20）

> 目的：fitlog 2.0 准备对外发布，找出「别人为什么选它」，据此排下一轮优化。
> 资料来源：三路网络调研（海外记录器 / 国内市场 / 用户痛点与趋势）。Reddit、知乎、小红书正文抓不到，
> 口碑部分多来自汇总文章（不少是竞品厂商写的），**价格和口碑当参考，不当定论**。标 ⚠ 的是未核实。

## 0. 结论

小 App 赢不了「内容多、AI、社交」，能守住的是 **快、可靠、数据归用户、懂真实健身房的器械**。
fitlog 在最后一条上已经领先市面几乎所有记录器（馆档案 + 就近取整 + 器械纪录按馆比），
但发布前有两个硬缺口：**公众用户没有任何数据保护（同步只通作者自己的 NAS）**、**换 App 进不来也出不去（只有自家 JSON）**。

一句话定位：**「认得你健身房的训练本」——按你这个馆真有的片子和器械记，离线、不注册、数据随时带走。**

## 0.5 一手反馈之后的修订（同日第二轮）

第二轮读了一手材料：国内见 [research-xunji-feedback-2026-10-20.md](research-xunji-feedback-2026-10-20.md)（App Store 约 2000 条 + 小红书约 25 篇 + V2EX），
海外见 [research-overseas-feedback-2026-10-20.md](research-overseas-feedback-2026-10-20.md)（Google Play 4456 条 + Reddit 2314 帖 / 约 4400 评论 + HN）。

**被证实的**
- 「换馆重量对不上」国内外都是真痛点：小红书相关帖动辄几百上千赞，用户在评论里问「这种数字在 App 上怎么记」；
  r/Hevy 2026-07 到 10 月约 25 条，变通办法都是把动作复制成「Leg Press (gym A)」。没有记录 App 真正解决。
- 「自动重量挂不出来」被两边点名：训记「设了只有 2.5 的片还让加 1.75」，Hevy「只勾了 5 kg 以上的片，还推荐 52.5」。
- 头号愤怒来源是丢数据：训记换手机 / 重装丢记录，Strong 改账号制清空多年记录，**纯本地的 FitNotes 也因备份要手动被骂**。
- 老练用户嫌弃 AI 教练和社交动态；被夸的是买断、无广告、录一组点一下。

**要修正的**
- 训记**有安卓版**（OPPO / 小米手环适配都有），不是「安卓靠第三方站」。国内安卓的空白比第一轮估计的小。
- 多馆档案不止 MacroFactor：**Alpha Progression 也有 gym profiles**（管器械可见性和单位）。
  **Hevy 2026-07 上线了馆标签（目前只是装饰），产品负责人公开说下一步做「按馆算 PR」**——窗口在收窄。
- 训记 2026 年推出 **Agent skill**（把训练数据交给 Codex 等 AI），但要会员，有人因此自己写了 App。
  「数据可以交给自己的 AI」本身成了卖点，fitlog 不必做 AI，只要导出免费、结构清楚。

**修订后的排期**（取代 §3 的顺序）

| 优先级 | 事项 | 依据 |
|---|---|---|
| P0 发布前 | **自动备份，且显眼**：首屏说清数据在哪、上次备份是什么时候；换机恢复走一遍 | 丢数据是两边头号差评；FitNotes 的教训 |
| P0 | **导入 Strong / Hevy CSV，导出 CSV**（免费），附一段「交给 AI 分析」的说明；训记导入先查它的导出是否要会员。**Strong 的 CSV 没有单位列**，导入时要按动作让用户确认 kg/lb（Hevy 在这里会把 lb 当 kg 导错，做对了本身是卖点） | 换 App 的门槛；训记把导出锁在会员里 |
| P0 | **首次体验两步：选馆 → 开练**；对外文案用用户的话：「换个馆不再以为自己变弱了」/ no more duplicate exercises per gym | 卖点藏在选馆弹层里；训记「第一次用有点懵」577 赞 |
| P1 | 单次训练「不计入纪录」开关（出差、测 1RM） | Hevy 官方说常被提，成本小 |
| P1 | 统计口径核对：滚动 12 个月 / 同期比较、哑铃容量算双边、所有动作都出 PR（先查 fitlog 现状） | 训记被点名的三个坑 |
| P1 | 透明的自动加重，「一档」取自馆档案 | 原 §3.2 第 4 条 |
| P2 | 器械可选「品牌 / 型号」备注；休息计时锁屏提醒；Health Connect | 重度多馆用户；收益较小 |
| 不做 | AI 教练、动态流、视频库、饮食 | 两边好评里「没有这些」本身被夸 |

**时间判断**：Hevy 做出按馆 PR 之前发布，差异点还能多保持一段；之后 fitlog 守的是 Hevy 路线图里没有的三样——
按片取整、单台器械的单位与一档、不联网不注册。

## 1. 竞品格局

| 类型 | 代表 | 卖点 | 大家吐槽 |
|---|---|---|---|
| 极简记录器 | Strong、Setgraph、FitNotes（安卓） | 快、干净 | Strong 免费只存 3 个模板，配片计算 / 图表要 PRO，CSV 导不回来；FitNotes 没自动备份 |
| 免费额度大 + 社交 | Hevy、Gravitus | 免费够用、全平台、买断便宜（Hevy $74.99 ⚠） | 动态流是噪音；免费图表只看 3 个月 |
| 算法排课 | Fitbod、Alpha Progression、RP Hypertrophy、Boostcamp Pro | 每组告诉你练多少 | 贵（RP $34.99/月）；算法不准、不能照 5/3/1 练 |
| 可编程 | Liftosaur（开源） | 脚本写任意进阶规则 | 要学脚本 |
| 国内专业 | 训记（iOS + 安卓，¥88 终身，一人开发）、练练/KeepStrong、练就 | 中文、买断便宜 | 安卓靠第三方站；越做越全（饮食、排行榜） |
| 国内大众 | Keep | 课程、跑步、AI 排课 | 广告多、力量记录是附属 |
| 新面孔 | MacroFactor Workouts（2025 底起） | **gym profiles：每个馆单独设片、杠、递增量** | 订阅 $11.99/月，独立评测少 ⚠ |

**行业共性**：模板数量 / 图表历史 / 记录次数被付费墙卡；从买断转订阅；AI 多是营销，真被认可的只有「按历史自动加重」；
Health Connect / Apple Health 只存一条训练摘要，存不下逐组重量。

## 2. fitlog 已经有、别人少有的（护城河）

| fitlog 能力 | 市面情况 |
|---|---|
| **馆档案**：每个馆的片子、单位、龙门架 / 器械 / 哑铃一档；个别器械单独设 | 主流记录器只有一套全局配片设置（Hevy、Strong、Liftosaur）；只有 MacroFactor Workouts 做了多馆档案。国内没看到 |
| **就近取整**：抄上次、复制、从计划开始、递减档、换馆，自动重量都落到能挂的数；手打照原样 | Liftosaur 有按片取整，但没有多馆；其余只有计算器 |
| **单位就是片子**，切单位 / 换馆不漂（135 lb → 60 kg → 切回还是 135） | Strong、Hevy 都能给单个动作设 kg/lb（Strong 还能把旧记录换算），但单位跟着动作走、要自己切；fitlog 的差别是单位跟着馆和片子走，换馆自动切 |
| **器械纪录只和同馆比**，杠铃 / 哑铃跨馆比 | 没找到任何主流 App 这么做，常见变通是建「腿举（A 馆）」这种重复动作 |
| 底稿抄上次并保持差值、递减档跟着记录走、交替组、拖动改数 | 多数只做「带出上次 + 点勾」 |
| 本地优先、不注册、离线、无广告、中英双语、安卓原生 | 主流都以云账号为中心；Strong / Hevy 在国内安卓要靠 Google Play |

这几条正好对上调研里两个独立来源都点名的空白：「每个馆一份器械档案并和记录打通，基本没人做好」「同一器械按馆分开，没有 App 支持」。

## 3. 对外发布前的缺口

### 3.1 必须补（不补就不该推给别人）

1. **数据保护**。现在的同步是 Tailscale 到作者 NAS，公众用户用不了；他们的数据只在手机 WebView 里，
   清数据 / 卸载 / 换机就没了。最常见的弃用原因之一就是丢数据。
   → 自动备份：定期把完整快照写到手机可见目录（下载 / 文档），可选 WebDAV（国内坚果云、自建 NAS 都能用）。
   设置里显示「上次备份：x 天前」。同步端点对外是关掉还是改成「填自己的服务器」，要定。
2. **换 App 的进出口**。现在只有自家 JSON 全量备份。
   → 导入 Strong / Hevy CSV（Hevy 自己就靠「能导入 Strong」抢用户）、训记导出格式 ⚠（先查它能导出什么）；
   导出 CSV（公开、一行一组）。正面回应「Strong 导出导不回来」这个点名痛点。
3. **馆档案的首次体验**。卖点藏在选馆弹层里，新用户不建馆就只看到「标准片」，等于没看到卖点。
   → 第一次开练时问一句「在哪练」，给几个常见配置（国内商业馆 kg 片 / 美式 lb 片 / 家用），一步建好。
   （单人自用时「不写教程文字」的约定，对外发布后要重新掂量。）

### 3.2 加深护城河（下一轮主菜）

4. **透明的自动加重，不用写代码**。Liftosaur 证明了需求，但要写脚本；Fitbod 一类是黑箱。
   fitlog 的独特组合：「次数到上限就加**这个馆这件器材的一档**」——加多少直接来自馆档案，别家做不出这个味道。
   规则只给几种：双进阶（8–12 次）、线性（每次 +1 档）、失败 N 次退一档。在底稿上标「该加了」，不自动替人改。
5. **馆档案再走一步**（先确认现状再做）：同一杠上 kg 片和 lb 片混挂；史密斯 / 腿举的「起始重量 / 杆重」按馆设；
   器械跨馆的粗略换算（可选，只做参考，不进纪录）。
6. **组间录入点击数**：量一下「做完一组」平均几下，对标 Strong 的两下。这是老手留下来的主因。

### 3.3 可以往后放

- 休息计时的锁屏 / 后台提醒（先确认现在 `RestBookmark` 在后台是否可靠）。
- Health Connect 写入训练摘要（只能写时长、动作，写不进逐组重量，收益小）。
- Wear OS 手表端（成本高）。

### 3.4 明确不做

AI 教练、社交动态、动作视频库、饮食记录。这些是大厂的战场，也是用户吐槽「臃肿」的来源；不做本身就是卖点之一。

## 4. 发布形态的待定项

- **收费**：参考价位是训记 ¥88 终身、Hevy $74.99 终身 ⚠。用户普遍反感「记录本身要订阅」。
  合理的形态是基础记录全免费、不限模板 / 历史；要收就收一次性买断。
- **分发**：国内安卓应用商店上架通常要软著和 App 备案 ⚠（V2EX 有独立开发者因此上不了架）。
  Google Play 或 GitHub Releases 是起步路线，要提前规划。
- **iOS**：Capacitor 理论上能出 iOS，但国内专业用户集中在 iOS（训记的主场），是否进场以后再看。
