# 健身房热修

用户在组间休息时用手机发消息，电脑在家。一轮的目标是几分钟内让手机上的正式 App 换成修好的版本，
改坏了能很快重打一个回退后的包。打包发布只有一条命令：`npm run gym:ship`（约 15 秒）。

## 一轮怎么走

1. **报了就当场修，不分轻重缓急，不往后放**（2026-11-23 用户定）。观感、手感、小想法也一样。
   需求有两种读法时先问一句再动手。改动大到组间做不完，就说清楚要多久、打算怎么拆，让用户定，不自己搁下。
   修完并经用户确认后，在 `docs/dev_notes_during_gym.txt` 记一笔：遇到了什么、怎么解决的。
   这份文件是已解决问题的记录，不是待办清单，里面不留没解决的条目。
2. **在主仓直接改**，不开工作树：下载目录和签名都认这台机器的主仓，少一层同步。改动尽量小。
3. **跑 `npx tsc --noEmit` 和 `npm run check`。** 完整 e2e 不在这里跑，留到回家合并前。
4. **设好 `GYM_NOTE` 再 `npm run gym:ship`。** `GYM_NOTE` 是下载页上「这个包改了什么」，一行一条，
   写用户拿着手机能看懂的话（「递减组现在会继承上一组重量」），不写文件名和提交号。没设脚本会拒绝打包。
   Bash 里：`GYM_NOTE=$'第一条\n第二条' npm run gym:ship`。
   它会打自用版正式签名包（走 `build-apk.ps1` 的闸门），从 APK 里读回构建戳，再替换掉下载页上的旧包。
   任何一步红了都不会发布。下载页永远只有最新的一个包。
5. **把下载地址和构建戳发给用户**：<https://maiji-desktop-trt.taild995c6.ts.net:8443/>。
   用户下载、覆盖安装，到「我的 › 首选项」最底下核对同一个戳，然后验证改动。
6. **用户说好了再提交。** 说不行：接着改；改不动就 `git stash` 或 `git checkout` 回退这次改动，
   重新 `gym:ship` 一个和改之前一样的包给用户装回去（下载页不留旧包）。

回复要短：用户在看手机，一条消息说清「改了什么、戳是多少、去哪下」。

## 当场不做的事

- **不抬 `versionCode`。** 安卓拒装 versionCode 更小的包，抬了就没法靠重打一个回退后的包装回去。版本号等回家正式发版时再动。
- **不悄悄改同步、备份、合并、数据迁移这一层。** 界面坏了能重打一个包装回去，数据写坏了装不回来。
  问题出在这一层时照样当场处理，但动手前先告诉用户会碰数据、可能的后果，等用户点头再改。
- **不加 Capacitor 插件、不改原生工程。** Kotlin 版本不对是运行时闪退，编译期看不出来（见 android-build skill 末尾）。
- **不走 Funnel、不把包放到 tailnet 以外。** 自用版包里带 NAS 地址和 API key。
- **不绕过 `gym:ship` 手敲 gradle 或直接拷 APK。** 「这个文件就是这次的代码」只有脚本里那道读回构建戳的检查能证明。

## 覆盖安装不会丢进行中的训练

工作台的内容改动即存，切后台和 pagehide 时再各存一次（`src/contexts/WorkoutContext.tsx`）。
用户切去浏览器下载时已经落盘，装完重开 App 会恢复。安装只换代码，不动 App 数据。

## 不通的时候

| 现象 | 原因和处理 |
|---|---|
| 手机打不开下载页 | 手机的 Tailscale 没开；或电脑睡了 |
| 脚本末尾说「下载目录还没挂到 tailnet」 | serve 配置没了。挂目录要管理员权限，让用户在电脑上跑脚本打印的那条命令（管理员 PowerShell） |
| 安装时报签名不一致 | 手机上不是正式签名的 personal 包。**别让用户卸载**，先问清手机上装的是什么 |
| `[X] 没有 .env.local` | 在工作树里跑了。回主仓跑 |
| 装上了但戳没变 | 下载页是浏览器缓存的旧页，或点开的是手机里之前下过的旧文件。让用户刷新页面重新下载 |

下载目录在主仓旁边：`..\fitlog-gym`（一个 APK 加一份每次重新生成的 `index.html`）。
别挪进 `%LOCALAPPDATA%`：桌面版 Claude 起的进程往那里写会被重定向，tailscaled 读不到，下载页全是 404。
